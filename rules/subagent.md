# Subagent 约束

## 基本规则

> 触发条件：任何 Subagent 派发与使用场景。

- 当前只允许 Subagent 进行只读探索、定位和交叉审查；所有代码、规则、配置、文档及 Notebook 的 Edit / Write 均由主代理执行。
- Subagent 不得执行任何 Git 命令（包括 `AGENTS.md`「版本控制（零容忍）」允许主代理使用的只读查询命令），不得启动服务、发送外部消息、修改任务状态或实施其他系统状态变更。
- 主代理与 Subagent 不重复同一范围的搜索：适合宽范围定位的工作交给 Subagent 后，主代理只复核其引用的关键证据，不重新做同一轮全量扫描。
- Subagent 的结论是只读调查材料，不构成业务规则确认、实施授权、代码修改或验证完成证明。

## 派发只读任务时

Prompt 必须包含：

1. **调查目标**：要定位、核实或交叉审查的具体问题，不使用“看看相关代码”等模糊表述。
2. **允许范围**：可读取的目录、模块、文件类型和搜索广度；禁止扩大到无关模块。
3. **禁止操作**：明确禁止 Edit、Write、NotebookEdit、Git、服务启动、外部发送和其他状态变更；即使 Subagent 的工具权限允许，也不得执行本规则禁止的操作。
4. **证据要求**：返回可定位的文件路径、行号、方法/字段名及支撑结论的当前代码或配置事实。
5. **边界要求**：区分已确认事实、推测、排除项和待确认业务决策；不得把历史实现直接写成目标业务规则。
6. **搜索广度与长度**：明确使用“窄（单文件/单符号）”“中（单模块）”“广（多个相关模块）”或“非常广（跨模块/多命名约定）”之一；默认输出不超过 2,000 个中文字符。超出时只保留证据索引、结论、排除项和未决事项，源码由主代理按位置复核。

只写“遵循项目规范”不能替代上述任务边界。

## 只读结论返回格式

- **调查范围**：实际读取或搜索的模块、目录和关键词。
- **已确认事实**：按业务调用时间线说明入口、关键调用、数据库读写点、外部交互和结果去向，并附文件路径与行号。
- **多入口/分支结论**：逐项列出每个已核查入口的路径、行号、Controller/API/Service 方法或前端事件/路由、触发条件、关键读写点和实际结果；已核查入口超过 10 个时可按相同结果分组，但不得省略组内入口；未覆盖入口单列，禁止用“部分入口”等未定义范围词概括局部证据。
- **排除项**：列出已核查但不支持当前假设的入口、平行实现或数据路径及排除依据。
- **风险与不确定项**：说明缺少什么代码、数据、配置或业务决策，不能以“可能”替代证据。
- **建议复核点**：只列主代理实施前必须亲自核实的关键位置，不声称已修改、已测试或已完成。

## 主代理复核

Subagent 的总结不能代替主代理判断。主代理必须：

1. 读取 Subagent 引用的关键代码或配置，确认路径、行号和当前内容仍然一致。
2. 对照用户指令、项目规则和业务证据，区分事实、技术建议与待确认政策。
3. 在实际编辑前亲自完成适用的路径核验、业务假设门控、A/B/C/R 档检查和风险判定。
4. 在实际编辑后亲自执行全方法审查、影响面审查和可用验证；不得把 Subagent 的只读调查表述为修改或测试证据。
5. 交叉审查或验证结论中，只有 Subagent 在当前会话实际执行过的检查才算通过；指定了检查命令的必须执行原命令，不得换成更快替代；未能运行的检查必须如实报告「未运行」，不得填入推断结论。

## 不合格处置

- Subagent 擅自修改文件、执行 Git 或其他状态变更：不采用其结果，停止该任务并由主代理核查实际状态；处置后必须在交付中记录该结论不可作为修改或验证证据。
- 结论缺少路径、行号或直接证据：退回补充只读证据，不据此修改；判断标准是每个结论都能定位到当前文件、行号或可复核配置事实。
- 搜索范围越界或与主代理重复：缩小任务范围，保留能够独立核验的证据；越界范围内返回的结论不得进入主代理决策。主代理同时核查越界范围内是否发生文件修改或状态变更；有则按第 1 条处置。
- 无法确认业务意图：标记待确认；仅在该决策会改变实施结果且现有证据无法确定时询问用户。
