# Subagent 约束

## 基本规则 [R-SUB-01]

> 触发条件：任何 Subagent 派发与使用场景。
> 动作要求：派发前确认只读边界；执行中监控工具调用；返回后由主代理复核关键证据；发现越界按「不合格处置」执行。
> 判断标准：每个 Subagent 任务都能对应到本文件的只读边界；返回结论能定位到当前文件:行号；越界或缺证据的结论不进入主代理决策。
> 失败或例外处理：无法确认只读边界、工具权限可能触发写操作、或任务需要跨模块扩大范围时，暂停派发并先补充边界。

- 当前只允许 Subagent 进行只读探索、定位和交叉审查；所有代码、规则、配置、文档及 Notebook 的 Edit / Write 均由主代理执行。判断标准：派发 Prompt 与实际工具调用均不包含 Edit、Write、NotebookEdit、Git、服务启动、外部发送或任务状态修改；出现任一即判定越界。
- Subagent 不得执行任何 Git 命令（包括 `AGENTS.md`「版本控制（零容忍）」允许主代理使用的只读查询命令），不得启动服务、发送外部消息、修改任务状态或实施其他系统状态变更。判断标准：Subagent 的调用记录中不存在任何 Git 命令；即使只读 Git 也不得执行。
- 主代理与 Subagent 不重复同一范围的搜索：适合宽范围定位的工作交给 Subagent 后，主代理只复核其引用的关键证据，不重新做同一轮全量扫描。判断标准：主代理后续只读取 Subagent 引用的文件:行号，或执行其明确指定的命令；确需扩大范围时，必须说明新增证据缺口，不得无差别重跑同一搜索。
- Subagent 的结论是只读调查材料，不构成业务规则确认、实施授权、代码修改或验证完成证明。判断标准：交付中不得把 Subagent 结论写成业务规则确认、实施授权、修改完成或验证通过；需要这些结论时由主代理重新取证。

## 派发只读任务时 [R-SUB-02]

> 触发条件：向 Subagent 派发只读调查任务时。

Prompt 必须包含：

1. **调查目标**：要定位、核实或交叉审查的具体问题，不使用“看看相关代码”等模糊表述。
2. **允许范围**：可读取的目录、模块、文件类型和搜索广度；禁止扩大到无关模块。判断标准：以任务点名的目录、包、文件为边界；需要跨模块时，在 Prompt 中逐项列出新增目录/包，不得默认扩大到全仓。
3. **禁止操作**：明确禁止 Edit、Write、NotebookEdit、Git、服务启动、外部发送和其他状态变更；即使 Subagent 的工具权限允许，也不得执行本规则禁止的操作。判断标准：派发 Prompt 与执行记录中均不出现上述操作。
4. **证据要求**：返回可定位的文件路径、行号、方法/字段名及支撑结论的当前代码或配置事实。判断标准：每个结论至少包含文件路径:行号，或可复核的配置/数据事实。
5. **边界要求**：区分已确认事实、推测、排除项和待确认业务决策；不得把历史实现直接写成目标业务规则。判断标准：四类信息分别标注，任一结论无法归入四类时退回补充。
6. **搜索广度与长度**：明确使用“窄（单文件/单符号）”“中（单模块）”“广（多个相关模块）”或“非常广（跨模块/多命名约定）”之一；默认输出不超过 2,000 个中文字符。超出时只保留证据索引、结论、排除项和未决事项，源码由主代理按位置复核。判断标准：必须写明四档之一；“广”需按目录/包列出模块名，不得只写“相关模块”；返回内容超过 2,000 个中文字符时只保留证据索引、结论、排除项和未决事项。

只写“遵循项目规范”不能替代上述任务边界。

> 动作要求：按 1–6 顺序在 Prompt 中逐项写全；缺失项先补齐再派发，不得以“遵循项目规范”替代。
> 判断标准：Prompt 逐项包含 1–6；搜索广度使用指定四档之一；输出长度上限写明；禁止操作逐项列出。
> 失败或例外处理：任一项无法确定时暂停派发，先向用户确认任务边界或补充证据。

## 只读结论返回格式 [R-SUB-03]

- **调查范围**：实际读取或搜索的模块、目录和关键词。
- **已确认事实**：按业务调用时间线说明入口、关键调用、数据库读写点、外部交互和结果去向，并附文件路径与行号。
- **多入口/分支结论**：逐项列出每个已核查入口的路径、行号、Controller/API/Service 方法或前端事件/路由、触发条件、关键读写点和实际结果；已核查入口超过 10 个时可按相同结果分组，但不得省略组内入口；未覆盖入口单列，禁止用“部分入口”等未定义范围词概括局部证据。权威定义见 `AGENTS.md`「批判性审查」第 8 项；本节是只读结论格式的细化。
- **排除项**：列出已核查但不支持当前假设的入口、平行实现或数据路径及排除依据。
- **风险与不确定项**：说明缺少什么代码、数据、配置或业务决策，不能以“可能”替代证据。
- **建议复核点**：只列主代理实施前必须亲自核实的关键位置，不声称已修改、已测试或已完成。

> 判断标准：返回内容包含上述 6 个部分；每个已确认事实附文件路径:行号；多入口逐项列出；未覆盖入口单列；建议复核点不声称已修改、已测试或已完成。
> 失败或例外处理：缺少任一必需部分、事实无法定位到当前文件/行号、或用“可能”替代证据时，退回补充只读证据，不据此修改。

## 主代理复核 [R-SUB-04]

Subagent 的总结不能代替主代理判断。主代理必须：

1. 读取 Subagent 引用的关键代码或配置，确认路径、行号和当前内容仍然一致。判断标准：每个引用都能在当前工作区打开，行号内容一致；不一致时以当前文件为准并退回补充。
2. 对照用户指令、项目规则和业务证据，区分事实、技术建议与待确认政策。判断标准：事实、技术建议、待确认政策三类分别标注；待确认政策不得进入实施。
3. 在实际编辑前亲自完成适用的路径核验、业务假设门控、A/B/C/R 档检查和风险判定。判断标准：A/B/C/R 档检查、业务假设门控、路径核验、风险判定均有记录；缺任一项不得编辑。
4. 在实际编辑后亲自执行全方法审查、影响面审查和可用验证；不得把 Subagent 的只读调查表述为修改或测试证据。判断标准：全方法审查、影响面审查、可用验证均有实际输出；不得以 Subagent 结论替代。
5. 交叉审查或验证结论中，只有 Subagent 在当前会话实际执行过的检查才算通过；指定了检查命令的必须执行原命令，不得换成更快替代；未能运行的检查必须如实报告「未运行」，不得填入推断结论。判断标准：每个检查能对应到实际命令/输出；未运行的检查标记“未运行”；不得用更快替代命令。

> 判断标准：5 项全部完成并留下可复核记录；Subagent 结论只作为线索，不作为修改、测试或验证证据。
> 失败或例外处理：任一项未完成时不得进入编辑；Subagent 结论缺路径/行号时退回补充。

## 不合格处置 [R-SUB-05]

- Subagent 擅自修改文件、执行 Git 或其他状态变更：不采用其结果，停止该任务并由主代理核查实际状态；处置后必须在交付中记录该结论不可作为修改或验证证据。判断标准：核查实际文件状态和 Git 状态；交付中记录“该结论不可作为修改或验证证据”；擅自修改的文件按主代理编辑规则重新审查。
- 结论缺少路径、行号或直接证据：退回补充只读证据，不据此修改；判断标准是每个结论都能定位到当前文件、行号或可复核配置事实。
- 搜索范围越界或与主代理重复：缩小任务范围，保留能够独立核验的证据；越界范围内返回的结论不得进入主代理决策。主代理同时核查越界范围内是否发生文件修改或状态变更；有则按第 1 条处置。判断标准：越界范围内结论不进入决策；主代理核查越界范围是否发生文件修改或状态变更。
- 无法确认业务意图：标记待确认；仅在该决策会改变实施结果且现有证据无法确定时询问用户。判断标准：仅当决策会改变实施结果且现有证据无法确定时询问用户；否则标记待确认并继续只读调查。
