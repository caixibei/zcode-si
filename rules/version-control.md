# 版本控制纪律

> Git 命令边界以 `~/.zcode/AGENTS.md`「版本控制（零容忍）」的穷尽白名单为唯一权威来源；本文件只补充敏感配置处理和 DB 字段变更同步细则，不另行维护可能漂移的命令列表。
>
> 触发条件：执行任何 Git 命令、处理敏感配置、编辑生产 profile 或进行 DB 字段变更时。
> 动作要求：先按 `AGENTS.md` 判定 L1/L2/L3 与 Git 白名单，再执行本文件对应细则；每一步保留可复核记录。
> 判断标准：Git 命令逐条对应白名单；敏感值不泄露；DB 字段链路每个触点有确认结果或“未验证”。
> 失败或例外处理：命令无法对应白名单、授权无法定位到文件/字段/任务、或字段缺口会影响持久化/回显/导入导出/测试时，停止执行并说明阻断。

## Git 只读原则 [R-VCS-01]

> 触发条件：执行任何 Git 命令前。
> 动作要求：先对照 `AGENTS.md` 穷尽白名单，再执行；不得根据本文件扩展命令形式。
> 判断标准：执行的命令可逐条对应白名单中的形式。
> 失败或例外处理：命令无法对应白名单形式时停止执行，向用户说明该命令不在白名单并给出白名单内的替代查询；不得以“只是查询”或“看起来只读”为由例外放行。

严格执行 `AGENTS.md`「版本控制（零容忍）」的穷尽白名单。白名单外的命令即使看起来只读也不得执行；`git branch` 仅允许最高级规则明确列出的查询形式，不得根据本文件自行扩展。
判断标准：会话中执行的全部 Git 命令均可逐条对应白名单形式；无法对应到白名单的命令不得执行。

## 敏感配置 [R-VCS-02]

> 触发条件：处理配置、密钥、token 或连接信息时。

未取得明确授权时，配置示例和仓库配置使用占位符，日志与用户可见输出始终脱敏。脱敏默认以 `[已脱敏]` 完全替代真实值；只有为区分多个候选值确有必要且原值长度大于 8 个字符时，最多保留首尾各 2 个字符，其余替换为 `***`，不得通过多段输出拼出完整值。判断标准：输出中真实值被 `[已脱敏]` 或“首尾各 2 字符 + `***`”替代；不得通过多段输出拼出完整值；原值长度不超过 8 个字符时不得保留首尾。

用户只要求“配置某个值”，但未明确目标文件、字段或存储方式时，只确认一个会改变落盘结果的关键问题；不得擅自选择环境变量、占位符、密钥管理服务或仓库配置。用户直接提供具体值并要求写入其点名的配置文件和字段，或批准了包含该位置与表示方式的精确差异，即视为本次存储方式已明确，不重复询问。判断标准：触发本段时只提出一个问题，且问题直接决定文件/字段/存储方式；用户回答前不写入任何文件、环境变量或密钥管理服务。

用户明确授权把真实敏感值写入指定配置文件时，必须同时满足：

1. 授权指向可识别的文件、字段和本次任务；用户直接提供值并要求写入，也构成明确授权。判断标准：授权文本能定位到文件、字段、本次任务；仅说“配置一下”不构成明确授权。
2. 写入前以 `git status --short` 和 `git diff -- <目标文件>` 的只读结果确认目标文件是否由版本控制跟踪及是否存在用户已有改动；跟踪状态不阻断已获授权的 L2 操作，也不得据此擅自修改忽略规则或撤销用户要求，但交付时须说明真实值可能随用户后续版本控制操作进入提交。判断标准：写入前已执行 `git status --short` 和 `git diff -- <目标文件>`；交付中说明跟踪状态和用户已有改动。
3. 只修改已授权位置，不把值复制到源码、注释、日志、测试夹具或其他配置文件。判断标准：写入后检索真实值，只在授权文件/字段出现；其他文件、注释、日志、测试夹具中为 0。
4. 严格采用用户授权的存储方式，不得擅自替换为环境变量、占位符或密钥管理服务。判断标准：存储方式与用户授权一致；环境变量、占位符、密钥管理服务未被擅自替换。
5. 文件内容按用户要求保留，不因会话结束自动恢复；该授权本身不延续到未来修改。判断标准：文件内容保留用户要求；会话结束不自动恢复。
6. 完成后说明本次按授权写入，并提醒用户维持访问控制和环境隔离；回复中不复述完整敏感值。判断标准：交付说明本次按授权写入并提醒访问控制；回复中无完整敏感值。

判断标准：6 项全部满足才可写入；任一不满足时停止并说明阻断。

生产 profile 的本地、可逆配置编辑属于 L2，不因文件名含 `prod` 自动升级为 L3；直接覆盖真实生产环境的关键业务数据或系统权限属于 L3。L3 的完整定义及"清表"边界见全局 `AGENTS.md`「操作风险与授权层级（L1/L2/L3）」。判断标准：生产 profile 本地可逆编辑按 L2；直接覆盖真实生产环境关键业务数据或系统权限按 L3；无法归类时按更高等级处理。

## DB 字段变更同步 [R-VCS-03]

触发条件：新增、删除或重命名字段时。动作要求：按下列链路逐项确认适用性并记录结果。通过标准：每个适用触点都有确认结果或“未验证”标记；不存在会改变字段含义、持久化、回显、导入/导出或测试结果且仍处于未处理状态的缺口（该情形按下方正文暂停实施并向用户说明）。

新增/删除/重命名字段前，按下列链路逐项确认适用性并记录结果：

```text
迁移脚本 → Entity → DTO → Mapper → Service → 前端 → 测试
```

任一适用触点尚未确认时，必须标记为“未验证”，不得声明字段链路完成；若该缺口会改变字段含义、持久化、回显、导入/导出或测试结果，暂停实施并向用户说明。

共享 Mapper 新增返回字段时：
1. 检查实体是否有对应字段映射
2. 检查其他调用方是否受影响
3. 注释字段在后续数据装配中的用途
4. 验证空值和历史数据兼容性
5. 验证字段在共享 Mapper 全部调用方的查询、导出和测试路径中无未同步触点

判断标准：上述 5 项全部有结果；第 1 项 Entity 映射存在，第 2 项全部调用方已列出并核对，第 3 项注释说明字段在后续数据装配中的用途和来源，第 4 项空值与历史数据兼容性已验证或有明确未验证标记，第 5 项查询/导出/测试路径逐项核对且无未同步触点；任一缺口影响字段含义/持久化/回显/导入导出/测试时暂停实施。
