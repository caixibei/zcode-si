# 前端工程规范

> 决策优先级见 `~/.zcode/AGENTS.md`「决策优先级」。注释标准见 `~/.zcode/rules/annotation.md`。

---

## 一、触发条件

以下任务触发本规范：

动作要求：命中任一场景时，先确认结构根因，再按本文件对应章节修改。通过标准：不跳过结构根因诊断，且每次修改能对应到本文件的具体章节。

- 元素被遮挡 / 溢出
- 查询区放不下字段
- 表格区域异常
- 按钮挤压 / 重叠
- 响应式布局失效
- 页面布局调整
- 样式异常修复
- 弹窗布局调整

---

## 二、布局修改方法论

布局修改前先确认遮挡、溢出、挤压或响应式异常的结构根因；优先调整 DOM 和布局容器，其次使用流式布局，最后才调整 CSS 尺寸。修改后在最小适用宽度和相关响应式断点验证。

---

### 2.1 页面运行时验证

- 触发条件：变更会被开发服务器渲染、提供、记录或影响浏览器交互时，才执行运行时验证；仅影响后端、测试、类型或工具链的变更不启动前端服务。
- 服务启动、页面预览和可预览代码变更的验证工具，以当前会话更高优先级的运行时工具约束为准；当前会话要求使用 `preview_*` 时，使用 `preview_start`、`preview_logs`、`preview_snapshot`、`preview_inspect` 等工具，不得用 Bash 或 Chrome DevTools 启动服务。
- Chrome DevTools MCP 的调用授权与未授权替代方式统一定义于「前端工程纪律」对应条目；本场景遵循同一授权前置（明确授权或明确要求）与 `preview_*`/静态解析/项目日志替代路径，不再重复展开。
- 服务已运行时，先确认服务状态；同一验证不得同时启动两套服务。工具不可用或页面无法访问时，记录具体端口、权限、登录、编译或网络阻断，不得要求用户代验后仍声称完成。
- 修改模板新增 `theme-name`、`hidden`、`disabled` 等绑定时，必须在 `data`、`computed` 或 `methods` 中声明对应成员；页面刷新（含热更新后再次刷新）后控制台不得出现该字段相关 Vue warning/error。
- 自定义 `el-input` 清空图标时，用户已授权使用浏览器检查工具后，必须与同页正常输入框的 `.el-input__clear` 对比位置、尺寸、`display` 和对齐方式；未授权时只能静态核对选择器和样式来源，不得声称完成运行时对比。
- 表格新增列后，用户已授权运行时检查且页面可访问时，读取最小适用宽度下的容器 `clientWidth`、内容 `scrollWidth` 和各表头实际宽度；地址、备注、服务范围、账户等长文本列设置宽度（建议 200px，最小 120px，长文本启用换行或省略号）并保留横向滚动；无法运行时验证的列，逐列记录为未验证项并说明阻断原因。
- 跨行或跨区重排字段时，组件必须归属目标布局容器；禁止仅用 `absolute`、`transform` 等视觉位移跨越原容器。验收时核对 DOM 父容器、定位上下文和运行时坐标；无法运行时以静态 DOM 结构审查替代并披露限制。内部组件尺寸变更导致父容器溢出、遮挡或挤压时，必须同步调整父容器尺寸或布局，验证标准是内容完整可见、无溢出隐藏。
- 跨行等分表单不得仅凭相同 `col` 类名判定对齐；必须核对各行 flex 子项数量、`flex-shrink`、`box-sizing`、边框和间距，并比较运行时列边界。修复时统一完整栅格、列轨道及收缩口径，禁止用控件宽度、`margin` 或 `transform` 逐列补偿。

## 三、低代码平台特殊约束

低代码平台生成的页面（如本项目的 `style:after` 区域）：

- 容器定位系统（`position` / `inset` / `z-index`）由平台控制
- 应通过平台自定义区域用 `order` / `flex-basis` 调整内容排列
- **禁止**覆盖容器定位方式（会引发 scoped style 特异性冲突，陷入 `!important` 叠加）

## 四、Vue / JavaScript 业务注释

修改 `<script>`、业务函数或承载复杂交互的 `<template>`/`.html` 时，按 `~/.zcode/rules/annotation.md` 执行函数全覆盖审查，其中第 1–15 项为通用段落（适用于所有语言），第 16–20 项为前端专属补充段落。前端文件必须同时覆盖通用段落和前端补充段落中适用的项。

公共 JavaScript 工具新增、修改或保留兼容 API 时，按 `~/.zcode/rules/annotation.md`「公共 API 与兼容入口注释」补齐 JSDoc 与最小使用示例；页面内简单单链路异步调用不因此强制添加示例。模板中简单绑定不强制注释；复杂权限表达式、不直观事件链和跨组件状态传递必须说明业务场景与结果去向。长业务函数不得因已有函数名或方法级 JSDoc 而出现连续多阶段无业务段落注释的断层。

## 五、组件选型

| 场景 | 推荐 | 说明 |
|------|------|------|
| 简单表单 | `el-form` + `el-form-item` | 内置校验、布局一致 |
| 复杂表格（编辑/筛选/导出） | `vxe-table` | 功能丰富，支持虚拟滚动 |
| 简单列表/展示 | `el-table` | 不过度引入 vxe-table |
| 弹窗编辑 | `el-dialog` + `el-form` | 统一交互模式 |
| 树形选择 | `el-tree-select` | 与后端接口格式一致 |

遵循现有Vue 2 / Element UI技术栈，不因局部修改迁移框架。

> 项目级 AGENTS.md 若有项目特定组件补充，以项目级为准；本表为通用默认。设计系统约束见「设计系统」。

## 六、响应式与状态

- Vue 2数组索引和动态属性使用`this.$set`
- 弹窗关闭时清理表单值和校验状态；判断标准：重新打开弹窗时表单为初始值且无上一次校验错误提示
- 表格刷新后按业务语义处理选中状态：查询条件变化或数据重载时清除选中；同数据局部刷新时保留选中并记录保留依据
- `vxe-table`配置稳定、唯一的`row-id`
- 查询/重置/分页/排序调用同一数据接口，保持总数口径一致
- 无依赖请求必须并行；有依赖时注释等待原因
- 多阶段异步处理应在结果完整且一致后再提交用户可见状态，避免中间结果造成闪烁、短暂错误或状态不一致。
- 增量加载必须区分首次加载与追加加载：追加期间保留已展示内容，只在增量区域反馈加载状态；不得以全局 loading、重置列表或重建容器替换既有内容。
- 为浮层、下拉、弹窗等单个组件修复样式时，使用组件专属 class 或实例范围选择器；不得为单点问题修改全局组件库选择器。
- 视觉异常先检查运行时的内容裁切、滚动位置、容器尺寸及计算后的 margin/padding，再修改布局；不得连续叠加偏移类样式掩盖结构问题。
- 存在并发请求时必须明确状态所有权；失去所有权的异步结果不得影响当前界面的数据、反馈或交互状态，组件销毁后同样不得回写。
- 字典或关联数据仅用于展示时，保留后端原始 ID/编码字段；写入独立 `*Label`/`*Name` 字段，业务判断、请求参数、排序和跳转始终使用原始值。
- 并行辅助请求须独立处理失败：单项失败仅回退该展示字段为原值并按原语义提示，不得中断其他映射或整张列表提交。
- 详情页/编辑页加载时，select 下拉选项必须在表单数据赋值之前或同一轮异步中加载完成；若选项在表单数据赋值之后才返回，select 组件首次渲染时无匹配选项，会显示"请选择"而非实际值。正确做法：先 await 选项加载，再赋值表单数据；或在 mounted 中先触发选项预加载，回调内再执行表单查询。
- 修改公共异步工具时必须保持既有调用方的异常与完成语义；需要演进 API 时，先评估调用方行为并提供可验证的迁移路径。
- 多端页面交互对齐时，下拉框数据源必须使用源端同一接口，不得因为目标端已有同名 API 文件就直接引用；同名 API 可能来自不同业务域（如 `wechatmodule/entrustManagement` vs `zygl/wtfgl`），接口返回的数据集不同，会导致下拉选项不一致。对齐时必须逐个下拉字段核对接口 URL、查询参数和响应数据。权威定义见 `~/.zcode/rules/business-assumptions.md`「多端数据来源一致性门控（强制）」执行流程。
- 多端页面的字段禁用/只读状态必须与源端一致；源端自动回填的字段（如银行信息）在目标端不得开放编辑，源端必填字段在目标端不得去掉必填标识。除 disabled/readonly/required 属性外，禁用态视觉呈现也必须一致：背景色（置灰）、文字颜色（变灰）、`cursor: not-allowed`、opacity/透明度、可聚焦性逐字段比对；目标端「仅 disabled 属性但无置灰样式」判为不合格——用户会把禁用字段误判为可点击却点不动的 Bug。验证方式：对比源端与目标端每个字段的 disabled/readonly/required 属性与禁用态视觉样式（运行时段比对 computed style 或截图）。权威定义见 `~/.zcode/rules/business-assumptions.md`「禁用/只读态视觉样式一致性（强制）」。
- 多端表单的动态显隐与联动（v-if/v-show 条件、字段联动链、低代码 `hidden` 绑定）必须复刻源端的触发条件，而不是复刻某一场景下的最终可见集；触发条件不一致会在业务场景变化时产生字段缺失或多余。显隐联动属于业务逻辑一致性，不属于本文件允许的布局/组件端适配差异，不得以屏幕尺寸、组件库或输入方式差异为由省略联动链。判断标准：相同输入组合下，A/B 两端每个字段的可见性、禁用态、禁用视觉样式逐字段一致。完整核验步骤按 `workflows.md`「多端业务一致性对齐」步骤 8 执行。
- 多端页面的前端自动计算与自动回填（公式、触发时机、精度舍入、单位换算）必须与源端同口径，计算结果参与提交时两端提交值必须一致；仅展示一致而提交口径不同会导致对端续办时数据漂移。

## 七、设计系统

- 主框架：Element UI 2.15；微前端按现有Element Plus版本
- 颜色与字号：使用设计变量，禁止硬编码
- 间距：4px倍数（4/8/12/16/24/32）
- z-index：弹窗2000+、tooltip3000+
- 样式：scoped，避免全局污染
- 类名：自定义用业务前缀，不覆盖组件库内置类

## 八、CSS 合并

同一文件、同一作用域中的重复选择器必须合并（不同@media断点和明确级联覆盖除外）。

触发条件：同一文件、同一作用域内存在重复选择器。动作要求：合并后保留级联效果，并按下方三条规则排序。通过标准：合并后同一节点渲染效果不变；不同@media断点与明确级联覆盖除外。

- `!important`高于普通声明
- 同优先级以后出现的为准
- 选择器按作用范围从大到小排列

纯CSS变更不要求业务注释，但必须检查同名class和作用域。

## 九、组件抽取标准

> 组件库选型（`el-form` / `vxe-table` / `el-table` 等）见「组件选型」。

### 必须抽取为独立 .vue 组件

| 场景 | 理由 |
|---|---|
| 弹窗/抽屉（el-dialog / el-drawer） | 新增功能或新页面必须抽取；历史页面 Bug 修复若抽取会扩大影响面，适用 `design-principles.md` 的 Bug 修复例外，可保留在原页面原位修复。 |
| 复杂表单（>10 个字段或含嵌套/联动逻辑） | 表单逻辑复杂时独立组件更易维护 |
| 可复用业务区块（在 2 个以上页面出现） | 避免代码重复，统一维护 |
| 选项卡内的独立业务面板 | 面板逻辑独立，不污染父组件 |

### 允许保留在主页面

| 场景 | 理由 |
|---|---|
| 简单查询条件（<5 个字段，无联动） | 不值得抽组件 |
| 页面级独有逻辑且无法复用 | 抽组件增加间接层但无收益 |
| 历史代码修复，抽组件会扩大影响范围 | 最小侵入优先，参见 `~/.zcode/rules/design-principles.md` 决策矩阵 |

### 组件通信规范

```text
父 -> 子：props（数据下沉）
子 -> 父：$emit（事件上报）
弹窗数据：props 传入初始数据，$emit 返回结果
```

### 组件文件组织

```text
views/模块名/
  ├── 页面名.vue              # 主页面
  ├── components/             # 页面级组件
  │   ├── XxxDialog.vue       # 弹窗组件
  │   ├── XxxForm.vue         # 复杂表单组件
  │   └── XxxDetail.vue       # 详情面板组件
  └── mixins/                 # 页面级混入（可选）
```

## 十、表单编辑区布局原则

触发条件：新增或修改表单编辑区布局时。动作要求：按下方三条原则选择容器结构、对齐方式和按钮区隔离方案。通过标准：表单项超过 4 个时使用多列或换行布局；同行业必填与非必填不靠缩进区分；底部操作按钮区不与表单内容区共享 flex 上下文。

- 表单项超过 4 个时，采用多列 grid 或 flex-wrap 布局
- 必填项与非必填项在同一行时，视觉权重一致（不靠缩进区分）
- 表单底部操作按钮区与表单内容区用独立容器隔离，不共享 flex 上下文

## 十一、前端工程纪律

- 触发条件：修复任一前端布局、样式或交互问题（含本文件「一、触发条件」列出的全部场景）后。动作要求：当前任务结束前必须总结、复盘并记录本轮处理过程中的经验和教训；记录至少包含触发场景、实际根因、采用修复、验证证据和可复用判断规则。判断标准：后续命中相同场景时先查阅并应用该记录，避免重复采用已证实无效的处理方式。
- 触发条件：修改任何前端源码、模板或样式时。未经用户在当前任务中明确许可，不得执行任何前端生产构建命令，包括但不限于：`cd <前端模块根目录> && NODE_OPTIONS="--openssl-legacy-provider --max-old-space-size=8142" ./node_modules/.bin/vue-cli-service build --mode production`。未获授权时只执行 Vue 模板/脚本解析、CSS 解析、类型检查或等效静态验证；通过标准是解析无语法错误且新增绑定存在于组件状态。获得明确授权后才可构建，并报告实际命令、退出码和警告。项目级 `AGENTS.md` 中记录的 `npm run lint` 仅是模块命令事实，不改变本条限制；前端源码修改后未经当前任务明确许可不得运行 lint。
- 触发条件：需要使用 Chrome DevTools MCP 检查 DOM、Network、Console、性能或浏览器交互，或进行页面运行时验证时。未经用户在当前任务中明确授权或明确要求，不得调用任何 `chrome-devtools` MCP 工具；用户明确要求调用时，先选择实际页面和 URL，再按工具流程检查。未获授权时改用 `preview_*`、静态解析、项目日志或已有运行时证据，并在交付中标明未使用 DevTools；不得以其他同类工具冒充 DevTools 验证。
- 触发条件：修改表格行高、padding、单元格尺寸、表头高度或固定列样式时。必须同步覆盖组件库独立渲染的全部实际 DOM 区域，包括 Element UI 的 `el-table__fixed`、`el-table__fixed-right`、`el-table__fixed-left`、`el-table__header-wrapper`、`el-table__body-wrapper`、`el-table__fixed-header-wrapper`、`el-table__fixed-body-wrapper`；主表和固定区域使用同一高度、padding 和 line-height。运行时可验证时，逐项比较表头、第一数据行和最后数据行的实际高度；任一对应区域不一致即验证失败。

## 最终原则

```text
结构问题不要用样式解决。
布局问题不要用尺寸掩盖。
工程问题不要用补丁堆叠。

正确 DOM -> 正确布局模型 -> 简单 CSS -> 长期可维护代码
```
