# multi-end-align

多端对齐任务的统一执行流程。本 skill 自包含 12 步核验与数据来源一致性要求；宿主 Agent 若加载了更高优先级的多端一致性规则，冲突时以该规则为准。

核心原则：**页面外观相似不等于对齐完成**。完成标准是「A 端提交的单据在 B 端可无差别回显并继续下一步操作」。

## 第零步：基线确认与分级

1. 沿路由配置确认源端与目标端实际加载组件：以路由 `component` 指向的文件为修改与验证对象。
2. 按字段规模分级：变更 ≤5 个字段或仅修复已有对齐 Bug 为 Tier 1，执行步骤 1、5、11、12 及受影响字段的步骤 4、6、7；变更 >5 个字段或新增完整功能端为 Tier 2，执行全部 12 步。
3. 输出初始修改文件清单与明确排除范围，不得默默扩大。

## 12 步核验表

| # | 核验动作 | 判断标准 |
|---|---------|---------|
| 1 | 源端运行时字段清单：运行时提取全部可见表单控件的 label、value、disabled，静态提取不可替代 | 无遗漏、无多余 |
| 2 | 目标端数据模型覆盖度：逐字段核对数据模型包含源端所有字段 | 缺失字段必须补齐 |
| 3 | 目标端模板绑定覆盖度：数据模型有字段不等于模板有绑定 | 未绑定字段不得声称对齐 |
| 4 | 字段顺序与标签：逐 Tab/分区对比字段顺序与中文标签（含括号、甲乙方等修饰词） | 标签逐字一致 |
| 5 | 下拉与列表/搜索查询契约：逐下拉字段核对接口 URL、参数、响应格式；列表查询的筛选条件、默认条件、分页参数、排序、总数口径 | 数据域同源，结果集一致 |
| 6 | 禁用/只读状态与禁用视觉样式：属性 + 背景色、文字色、cursor、opacity、可聚焦性逐字段比对 | 仅 disabled 无置灰样式判为不合格 |
| 7 | 校验规则：必填性、格式、长度/范围、自定义校验消息 | 一端拦截的非法值另一端不得放行 |
| 8 | 动态显隐规则：提取完整联动链（触发字段、条件、受影响字段、时机），复刻触发条件而非最终可见集 | 相同输入组合下逐字段可见性一致 |
| 9 | 业务逻辑与自动计算：公式、触发时机、精度舍入、单位换算 | 计算结果与提交口径两端一致 |
| 10 | 流程步骤与操作入口：状态机、各状态可用操作、按钮禁用条件、防重复提交与操作确认防护 | 任一端可达路径不在另一端断链 |
| 11 | 提交契约：保存/提交接口 URL、入参字段名、必填性、枚举与状态值域、单位精度、附件关联；目标端缺业务专用方法时同次补齐 | A 端提交值域落在 B 端可识别值域内 |
| 12 | 运行时验证与跨端接力闭环：逐 Tab 截图比对；A 端真实提交后 B 端打开验证回显、显隐、禁用、续办 | 无未知枚举、必填缺失、校验阻断、流程断链 |

核验中发现的差异必须标记为「业务一致 / 合法端适配 / 待确认 / 业务偏差」四类之一，不得静默处理。

## 低代码生成页面分歧速查

低代码平台生成的页面独立实现、不复用共享 API，高频分歧：调用通用 `insertOrUpdate` 而非业务专用接口、状态值硬编码与字典不一致、缺少前置校验接口调用、弹窗输入值未传给后端、标签由 `label_XXX` 类变量控制、API 路径前缀与源端不一致。对每处操作逐个比对后端接口 URL、入参结构和状态值口径，不得因「低代码独立实现」跳过比对。

## 禁止行为

- 仅比对数据模型字段就宣称一致；仅读静态 v-model 断言字段列表（低代码页面标签由 `label_XXX` 类变量控制）
- 假设数据源一致：同名 API 文件可能来自不同业务域或模块前缀，数据集不同
- 仅复刻最终可见集，不对齐动态显隐触发条件与联动链
- 联网搜索业务规则（业务规则以代码、数据库或用户确认为准）
- 未验证跨端接力闭环就宣称完成
- 用「部分入口」等未定义范围词概括局部证据

## 最终验证标准与交付

- 目标端运行时字段集、顺序、标签、数据源、查询契约、校验、显隐、自动计算、禁用状态与视觉样式与源端完全一致
- 跨端接力闭环通过：任一端提交的单据在其他端可完整回显并继续下一步操作
- 差异分类记录：业务一致 / 合法端适配 / 待确认 / 业务偏差；待确认项须取得用户决策后才能继续受影响修改
- 首次对齐完成后，把已对齐项、未对齐项、待确认业务决策记入 memory（参照既有同类对齐记录的组织方式），供后续会话接续
