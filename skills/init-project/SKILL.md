# 初始化项目上下文

## 执行判据（本技能通用） [S-INIT-01]

- **触发条件**：使用本技能处理其 description 所述任务时。
- **动作要求**：按本技能正文的步骤、约束和输出格式执行；涉及写文件、Git、外部发送、用户确认或其他状态变更时，先满足正文对应边界。
- **判断标准**：本技能要求的输入、步骤、输出/产物和检查项全部完成，并在回复或交付中给出可定位证据；未完成项标明阻断。
- **失败或例外处理**：前置条件不满足、信息缺失或用户未确认时暂停并说明缺失项，不得跳过、伪造或把未验证表述为完成。

提取日常开发最常用的项目事实，生成或更新项目根目录的 agent 指令文件。文件名以项目现状为准：默认 `AGENTS.md`，项目已有其他等价指令文件命名时沿用既有文件。它是高频上下文索引，不是企业规范手册、排查流程集合或业务知识库。

## 触发与排除 [S-INIT-02]

> 触发条件：执行本节流程时。
> 动作要求：按本节步骤、约束和示例执行；涉及用户确认、写操作、外部调用或其他状态变更时先满足前置条件。
> 判断标准：本节要求的步骤、输出或检查项全部完成，并能定位到实际产物或证据；未完成项标明阻断。
> 失败或例外处理：前置条件不满足或信息缺失时暂停并说明缺失项，不得跳过或伪造结果。

适用于创建、审查或更新项目根目录的 agent 指令文件（`AGENTS.md` 或项目实际采用的等价命名）。

不用于：

- 写跨项目个人原则；这类内容归用户级指令文件（ZCode 环境为 `~/.zcode/AGENTS.md` 等等价文件）或 rules。
- 写多步骤方法；这类内容归 skill。
- 推测业务规则、权限口径、部署策略或历史决策。

## 最小动作 [S-INIT-03]

> 触发条件：执行本节流程时。
> 动作要求：按本节步骤、约束和示例执行；涉及用户确认、写操作、外部调用或其他状态变更时先满足前置条件。
> 判断标准：本节要求的步骤、输出或检查项全部完成，并能定位到实际产物或证据；未完成项标明阻断。
> 失败或例外处理：前置条件不满足或信息缺失时暂停并说明缺失项，不得跳过或伪造结果。

1. **确认现状**：项目根目录已有 `AGENTS.md` 或其他等价指令文件时先读取，再让用户选择 `审查`、`补充` 或 `重写`；禁止默认合并或静默覆盖。目标文件优先级：项目既有指令文件 > 用户本次指定的文件名 > 默认 `AGENTS.md`。
2. **提取事实**：优先从构建文件、启动入口、开发脚本和主源码组织确认技术栈、启动方式、端口和高频模块。
3. **标记未知**：业务边界、角色权限、生产部署、外部系统和历史决策没有明确证据时，列为待确认。
4. **控制体积**：只保留高频事实。150 行是软性上下文预算（超出前必须先完成去重和外移长流程；它不是硬截断线，见「常见误用」表）；不删除会影响开发决策的已确认约束。

推荐骨架：

```markdown
# AGENTS.md - {项目名}

## 技术栈
- {语言、框架、关键依赖}

## 入口与启动
- {入口路径、启动命令、端口}

## 核心模块
- {模块名}：{有证据支持的一句话职责}

## 待确认
- {无法从仓库事实确认的信息}
```

目标文件名不是 `AGENTS.md` 时（如项目沿用其他既有命名），骨架标题同步替换为实际文件名，其余结构不变。

> 失败或例外处理：前置条件不满足或信息缺失时暂停并说明缺失项，不得跳过或伪造结果。

只有出现以下条件时，先说明影响并请用户确认，再替换或删除内容：

- 删除已有业务规则、运行约束或安全约定；
- 改写权限、生产部署、外部系统或数据安全相关描述；
- 将无法从代码验证的历史决策写为项目事实。

仅提取事实、去重、修正文案或新增明确入口信息时，不要求完整设计流程；仍需先读目标文件。

## 停止条件 [S-INIT-05]

> 触发条件：执行本节流程时。
> 动作要求：按本节步骤、约束和示例执行；涉及用户确认、写操作、外部调用或其他状态变更时先满足前置条件。
> 判断标准：本节要求的步骤、输出或检查项全部完成，并能定位到实际产物或证据；未完成项标明阻断。
> 失败或例外处理：前置条件不满足或信息缺失时暂停并说明缺失项，不得跳过或伪造结果。

出现以下结果即可结束：

- 已知用户选择为审查、补充或重写；
- 高危替换项已确认，或无需替换；
- 技术栈、入口和模块描述都有文件证据；
- 未知业务信息已标记；
- 已说明候选内容与验证方式。

不要继续罗列完整目录树、API 列表、函数签名、历史决策或长教程。

## 常见误用 [S-INIT-06]

> 触发条件：执行本节流程时。
> 动作要求：按本节步骤、约束和示例执行；涉及用户确认、写操作、外部调用或其他状态变更时先满足前置条件。
> 判断标准：本节要求的步骤、输出或检查项全部完成，并能定位到实际产物或证据；未完成项标明阻断。
> 失败或例外处理：前置条件不满足或信息缺失时暂停并说明缺失项，不得跳过或伪造结果。

| 误用 | 正确做法 |
|---|---|
| 已有文件时默认增量合并 | 先让用户选择审查、补充或重写。 |
| 新项目也进入完整开发状态机 | 只提取事实；高风险替换才升级。 |
| 按目录名称猜模块职责 | 从构建声明、入口和源码关系验证；不确定就标为待确认。 |
| 把 150 行当作硬截断线 | 将其作为压缩信号，保留必要事实。 |
| 把全部规则和文档复制进主文件 | 长流程与领域细则交给 skill/rules。 |
