# 深度脑暴

## 执行判据（本技能通用） [S-DBS-01]

- **触发条件**：使用本技能处理其 description 所述任务时。
- **动作要求**：按本技能正文的步骤、约束和输出格式执行；涉及写文件、Git、外部发送、用户确认或其他状态变更时，先满足正文对应边界。
- **判断标准**：本技能要求的输入、步骤、输出/产物和检查项全部完成，并在回复或交付中给出可定位证据；未完成项标明阻断。
- **失败或例外处理**：前置条件不满足、信息缺失或用户未确认时暂停并说明缺失项，不得跳过、伪造或把未验证表述为完成。

深度脑暴用于高影响决策，防止过早收敛。它的深度来自足够证据、事实与假设分离、以及对关键结论的反驳，不来自固定轮次、固定 agent 数量或固定工具链。

## 触发与排除 [S-DBS-02]

> 触发条件：执行本节流程时。
> 动作要求：按本节步骤、约束和示例执行；涉及用户确认、写操作、外部调用或其他状态变更时先满足前置条件。
> 判断标准：本节要求的步骤、输出或检查项全部完成，并能定位到实际产物或证据；未完成项标明阻断。
> 失败或例外处理：前置条件不满足或信息缺失时暂停并说明缺失项，不得跳过或伪造结果。

仅在用户明确输入 `/deep-brainstorming` 或明确点名“用 deep-brainstorming”时触发，且问题同时满足下列任一项：影响会改变持久化数据、权限、金额、状态流转、工作流或对外契约；依赖 3 个以上相互作用的因素；根因经一轮常规排查仍未定位。

不触发：

- “分析一下”“帮我看看”等普通分析请求；
- 单文件查找、函数解释、拼写或明确局部修复；
- 已有明确方案且用户只要求执行。

用户未显式调用时，使用普通分析或调试流程。

## 最小分析闭环 [S-DBS-03]

> 触发条件：执行本节流程时。
> 动作要求：按本节步骤、约束和示例执行；涉及用户确认、写操作、外部调用或其他状态变更时先满足前置条件。
> 判断标准：本节要求的步骤、输出或检查项全部完成，并能定位到实际产物或证据；未完成项标明阻断。
> 失败或例外处理：前置条件不满足或信息缺失时暂停并说明缺失项，不得跳过或伪造结果。

1. **定界**：确认要做出的决策、成功标准和不可突破约束。
2. **取证**：只选择能消除关键不确定性的证据来源。
3. **推理**：区分事实、假设和推论；关键结论保留可追溯来源。
4. **反驳**：为每个会改变方案选择的结论寻找相反证据或替代解释。
5. **呈现**：说明方案、收益、代价、风险和剩余不确定性，等待用户决定。

不预设调查轮数、agent 数量、证据维度、MCP 或外部工具。每次只增加能改变当前结论的一项调查。

## 证据与推理 [S-DBS-04]

> 触发条件：执行本节流程时。
> 动作要求：按本节步骤、约束和示例执行；涉及用户确认、写操作、外部调用或其他状态变更时先满足前置条件。
> 判断标准：本节要求的步骤、输出或检查项全部完成，并能定位到实际产物或证据；未完成项标明阻断。
> 失败或例外处理：前置条件不满足或信息缺失时暂停并说明缺失项，不得跳过或伪造结果。

| 类型 | 要求 |
|---|---|
| 事实 | 有代码、数据、日志、文档或用户确认来源。 |
| 假设 | 明确标记，并说明何种证据能验证或推翻。 |
| 推论 | 说明依赖哪些事实或已验证假设。 |

可按实际缺口选择代码搜索、业务上下文、历史经验、数据验证或外部参考。某维度不会改变决策时不搜；工具不可用时说明证据缺口，不以工具名称代替结论。

详细模板仅在需要时读取：

- [证据搜集](references/sweep-agents-guide.md)
- [推理参考](references/reasoning-guide.md)
- [独立审查](references/analysis-reviewer-prompt.md)

## 风险升级 [S-DBS-05]

> 触发条件：执行本节流程时。
> 动作要求：按本节步骤、约束和示例执行；涉及用户确认、写操作、外部调用或其他状态变更时先满足前置条件。
> 判断标准：本节要求的步骤、输出或检查项全部完成，并能定位到实际产物或证据；未完成项标明阻断。
> 失败或例外处理：前置条件不满足或信息缺失时暂停并说明缺失项，不得跳过或伪造结果。

只有出现以下条件时才补充调查或独立复核：

- 未验证前提会改变推荐方案或风险等级；
- 反驳成立，需新证据才能继续判断；
- 结论涉及安全、数据一致性、权限、金额、状态、事务、并发、API 或跨模块行为；
- 用户将依据结论进行不可逆操作。

只读子代理可独立搜集或复核；主代理负责综合和写入。不得要求 Git 写操作、worktree、提交、推送或子代理编辑。

## 停止条件 [S-DBS-06]

> 触发条件：执行本节流程时。
> 动作要求：按本节步骤、约束和示例执行；涉及用户确认、写操作、外部调用或其他状态变更时先满足前置条件。
> 判断标准：本节要求的步骤、输出或检查项全部完成，并能定位到实际产物或证据；未完成项标明阻断。
> 失败或例外处理：前置条件不满足或信息缺失时暂停并说明缺失项，不得跳过或伪造结果。

满足以下条件即可停止：

- 决策问题和约束清楚；
- 关键结论有证据或明确标为待确认；
- 已反驳会影响方案选择的结论；
- 方案、风险和剩余不确定性已呈现；
- 用户下一步选择已明确，或问题仍缺少决定性证据。

用户批准方案前，停留在分析层，不实现、不改代码。不要为了“更深入”继续搜集不会改变结论的信息。本约束仅在用户显式调用本技能时生效；与 `~/.zcode/AGENTS.md` 冲突时以 AGENTS.md 为准。

## 常见误用 [S-DBS-07]

> 触发条件：执行本节流程时。
> 动作要求：按本节步骤、约束和示例执行；涉及用户确认、写操作、外部调用或其他状态变更时先满足前置条件。
> 判断标准：本节要求的步骤、输出或检查项全部完成，并能定位到实际产物或证据；未完成项标明阻断。
> 失败或例外处理：前置条件不满足或信息缺失时暂停并说明缺失项，不得跳过或伪造结果。

| 误用 | 正确做法 |
|---|---|
| 普通“分析一下”自动进入重流程 | 只有显式调用才触发；其余走轻量分析。 |
| 先选 DB 锁或 Redis，再找理由 | 先确认决策问题和证据缺口，再比较方案。 |
| 固定 5 轮、2 个 agent 或指定 MCP | 仅使用当前证据缺口所需的调查。 |
| 把假设写成根因 | 标为假设，附验证方式。 |
| 找到一个可疑点就停止 | 反驳关键结论；仅当反驳后仍存在会改变方案选择的证据缺口时，补搜该缺口；证据已能支撑判断时不补搜。 |
| 用户尚未确认就开始实现 | 呈现方案与不确定性后停止。 |
